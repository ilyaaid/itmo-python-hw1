# P4. Развёртывание на Helios с контролем качества доставки

В работе вместо Helios ИТМО используется [хостинг Рег.ру](https://www.reg.ru/hosting/). GitHub Actions собирает сайт через `mkdocs build --strict`. Основная ветка публикуется в корень сайта на Рег.ру и в GitHub Pages. Ветки для предпросмотра публикуются только на Рег.ру.

## Выкладка и проверка

- GitHub Actions передаёт сборку через `rsync` поверх SSH. Пайплайн использует отдельный ключ выкладки из секрета `DEPLOY_KEY`. Адрес сервера и SSH-логин передаются через `DEPLOY_HOST` и `DEPLOY_USER`.
- Каждая ветка получает отдельный каталог на сервере и поддомен `preview-<имя>-<хеш>.aleldm.online`. Хеш различает ветки, чьи имена превращаются в одинаковый префикс. После удаления ветки её preview удаляется.
- После публикации healthcheck запрашивает публичный URL и проверяет HTTP 200 и наличие контрольной строки в HTML. Строка задаётся переменной `HEALTHCHECK_EXPECTED_TEXT`. По умолчанию используется «Моя документация». Ошибка запроса, другой код ответа или отсутствие строки завершают job с ошибкой.

## Откат на Рег.ру

Каждая успешная замена каталога сохраняет прежнюю основную версию на сервере. Для демонстрации отката нужно последовательно выложить две версии с различимым содержимым, запустить **Restore previous published version** и показать, что сайт снова отображает содержимое предыдущей версии. После восстановления workflow запускает healthcheck. Ссылку на успешный запуск и результат проверки нужно добавить в отчёт. Workflow **Publish an earlier commit** позволяет собрать и опубликовать указанный коммит из истории `main`.

## Сравнение площадок

| Критерий | GitHub Pages | Рег.ру |
| --- | --- | --- |
| Время доставки | Ожидает замера из блока **GitHub Pages** в резюме запуска | Ожидает замера из блока **REG.RU** того же запуска |
| Надёжность | Готовый артефакт передаётся сервису Pages для публикации. После этого CI проверяет публичный ответ | Файлы передаются во временный каталог, сайт переключается после завершения передачи. Прежняя версия доступна для отката |
| Удобство отладки | В Actions доступны логи сборки, публикации артефакта и healthcheck | В Actions доступны логи `rsync`, SSH и healthcheck. По SSH можно дополнительно посмотреть каталоги и резервную копию |

Оба таймера измеряют время этапа публикации вместе с healthcheck. Выкладка на Рег.ру запускается после успешной проверки GitHub Pages. Фактические значения и ссылку на запуск нужно добавить после выкладки одного и того же коммита на обе площадки.

## Что происходит при обрыве

При обрыве загрузки основной версии на Рег.ру посетители продолжают видеть прежнюю версию. Повторный запуск очищает недогруженный временный каталог. При остановке серверного скрипта между двумя переносами сайт может временно стать недоступным. Если переключение прошло, а healthcheck упал, CI отмечает запуск как неуспешный. Вернуть прежнюю версию можно ручным откатом. Preview загружается прямо в каталог поддомена, поэтому при обрыве часть файлов может остаться от предыдущей сборки.

В GitHub Pages при обрыве до передачи артефакта среде публикации продолжает работать предыдущий деплой. Если запуск прервался после передачи артефакта, фактическое состояние проверяется по статусу деплоя и содержимому публичной страницы. Внутреннее переключение версии выполняет сервис Pages.
