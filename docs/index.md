## Задание 1. Генераторы статических сайтов для публикации результатов исследований

### Цель работы

Исследовать [**генераторы статических сайтов**](https://jamstack.org/generators/) (SSG) на Python как инструмент публикации результатов экспериментов и сопровождающих их исследовательских материалов; освоить автоматизацию сборки и развёртывания сайта средствами CI/CD, в том числе на отечественных платформах и хостингах.

### Постановка задачи

На основе материалов, опубликованных по ссылке [https://disk.yandex.ru/i/RRaTxrn5psk7ZQ](https://disk.yandex.ru/i/RRaTxrn5psk7ZQ) и представленных в данной теме, создать и развернуть на GitHub Pages или аналоге (см. задание P1) собственный статический сайт, используя один из генераторов статических сайтов на Python. Автоматизировать процесс деплоя и реализовать развёртывание на отечественный статический хостинг (подсказка: посмотрите экшен «Static HTML»).

Ответы на вопросы исследовательских заданий и результаты практических заданий отразите в отчёте.

---

### Ход работы

1. Установить Python актуальной версии, проверить работоспособность `pip` (может запускаться как `pip` или `pip3`) и `virtualenv`.
2. Установить `virtualenv`, если он отсутствует: [https://virtualenv.pypa.io/en/latest/installation.html](https://virtualenv.pypa.io/en/latest/installation.html).
3. Создать каталог проекта, развернуть в нём виртуальное окружение, активировать его.
4. Зафиксировать зависимости: `requirements.txt` с точными версиями пакетов либо `pyproject.toml` с lock-файлом (`uv`, `poetry`). Добавить `.gitignore` (виртуальное окружение, каталоги сборки `site/`, `_build/`, кэш).
5. Установить MkDocs (или иной выбранный генератор) и создать каркас сайта.
6. Проверить локальную сборку: `mkdocs serve` для предпросмотра, затем `mkdocs build --strict`. Режим `--strict` превращает битые ссылки и предупреждения в ошибку сборки — именно это поведение требуется в CI.
7. Инициализировать репозиторий и отправить изменения на GitHub.
8. Настроить GitHub Actions. В настройках репозитория переключить **Pages → Source = GitHub Actions**. Разобраться в различии двух подходов к публикации: push в ветку `gh-pages` (`peaceiris/actions-gh-pages`) и официальная связка `actions/upload-pages-artifact` + `actions/deploy-pages`.
9. Создать новый сервер или активировать аккаунт на Helios ИТМО.
10. Скорректировать YAML-файл workflow под целевую площадку развёртывания.
11. Настроить базовый URL (`site_url`, `base_url`, `use_directory_urls`). Типичная ошибка: сайт корректно работает на GitHub Pages и ломается при размещении в подкаталоге на Helios.
12. Проверить результат развёртывания не только визуально: код ответа HTTP, наличие контрольной строки в HTML, работа поиска, корректность отображения формул при недоступности внешних CDN.
13. Добавить лицензии — раздельно на контент (например, CC BY 4.0) и на код (MIT, Apache 2.0).
14. Выполнить отладку, зафиксировав в отчёте возникшие ошибки и способы их устранения.
